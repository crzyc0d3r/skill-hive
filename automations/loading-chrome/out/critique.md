# Loading chrome critique

Compared the loading screenshots with the loaded screens in docs/parity/screenshots/light and dark.

- Library keeps the search field, All / Enabled / Available filters, and the grid and list toggles. The data region is six skill-card skeletons: a title line, two description lines, and tag pills. That matches the loaded card grid.
- Dashboard keeps Good day and the four action links. The data region is four stat cards (label, value, icon) and activity rows (mark, title, description). That matches the loaded dashboard.
- Settings keeps the tab strip. The data region follows Appearance: a theme row, a text-size row, and a language row. There is no extra table.
- Install keeps the tab strip. The data region is the local-folder form: a label, a full-width field, and two buttons. That matches install-local.
- Endpoints keeps the probe stepper. The data region is kind lines, endpoint rows, the secret form, and price lines.
- Effectiveness keeps the title and Show details. The data region is a grade block, four stats, and a radar-shaped chart.
- History keeps Set baseline. The data region is a chart outline and a three-column table.
- The job banner on the dashboard reads Syncing skills… 40% · 2 of 5, with Cancel and a progressbar at 40. It is a bordered popover banner, not a lowercase id.
- Light and dark use the same structure. The sidebar runs the full height and the status bar stays visible. Shimmer stops under prefers-reduced-motion.

The breadcrumb and the page heading both show the screen name, which is the same pattern as the loaded screens.
